# ベース・レジストリの指定について（令和3年）

令和３年５月26日 ／ 内閣官房情報通信技術（IT）総合戦略室

> アドレス（住所・所在地）をベース・レジストリとして指定した最初の決定文書（ABR の出発点）。
> 本指定は後に「ベース・レジストリの指定について（令和5年7月7日デジタル庁告示第12号）」で見直された。

## 1. 経緯

令和２年12月に策定したベース・レジストリ・ロードマップ（以下「ロードマップ」という。）においては、ベース・レジストリの重点整備対象候補として、個人や法人等、12の分野を例示していた。内閣官房情報通信技術（IT）総合戦略室（以下「IT総合戦略室」という。）においては、ベース・レジストリ指定に向け、ロードマップにおける重点整備対象候補のうち、社会的ニーズ、経済効果、即効性の観点に基づき、具体のデータの抱える課題についてデータホルダーの関係省庁と調整しながら検討を進めてきたところである。

## 2. ベース・レジストリ運用イメージ

ベース・レジストリ運用イメージとしては、基本的には以下の３類型が考えられる。指定を受けたベース・レジストリについては、それぞれの現状のデータ整備状況や特性等を勘案し、最も適した運用形態を検討し、整備を進めていく。

1. 各省庁等の保有するデータベース（以下「DB」という。）又はネットワークからキャッシュでデータを取得し活用する方法
2. ベース・レジストリカタログとの連携で活用する方法
3. 各省庁の保有するDBからデータ等をマッシュアップし、新たにベース・レジストリDBを構築・運用する方法

## 3. ベース・レジストリの効果

ベース・レジストリの効果としては、ロードマップで述べたように、以下のような効果を想定している。

1. ワンスオンリーの実現 — 行政手続きのワンスオンリーが実現し、申請者は再入力の時間・コストの削減、エラー処理の防止が図られる。
2. 行政におけるシステム重複投資の削減 — 各府省が各種法令の目的のために収集・整備・更新していたデータを、ベース・レジストリとして一体運用でき、重複投資の削減が図られる。
3. 社会の情報基盤としての貢献 — 行政だけでなく民間も活用できるデータを社会の情報基盤として共有・利活用することにより、社会コスト全体の削減に寄与する。

また、現在は各府省がそれぞれの業務を規定する各種法令の目的で整備・運用している地図情報（個別地図情報）やアドレス情報において、町字・地番情報を活用する際に表記の揺れ等が存在することから、スムーズな情報連携が困難となっている。このため、町字・地番を含むアドレス情報をアドレスのベース・レジストリとして整備して個別地図情報と連携することにより、ある台帳の地図情報が更新されれば、それと連動して別の台帳の地図情報の更新も可能となり、個別地図情報の更新に係る負荷低減等が図られる。

これら正確かつ最新に保たれたアドレス・ベース・レジストリの情報が社会全体で共有されることにより、行政だけでなく民間においても、例えば物流業界における配送先情報や郵送物に必要なアドレス情報の正確性担保により配送間違いの削減が図られるなど、社会全体のコスト削減につながる。

## 4. ベース・レジストリ指定の考え方

ロードマップでは、①多くの手続きで利用されるデータ、②災害等の緊急時に必要なデータ、③社会的・経済的効果が大きいデータ、の観点からベース・レジストリの重点整備候補を選定した。本指定では、主に以下の視点に基づきベース・レジストリとなるデータを指定する。

1. 社会的ニーズ — 多くの手続きで利用される、社会全体で活用する場面が多い、災害等の緊急時に必要、など社会的ニーズの高いデータ
2. 経済効果 — データ整備による効率化や新たな価値創出などで経済インパクトが大きいデータ
3. 即効性 — 既に整備・公開済みのオープンデータ、クレンジング不要な高品質データなど、すぐ利活用可能なデータ

ベース・レジストリ指定に際しては、指定当初から要件の網羅的・完全な具備は求めず、段階的に向上を図ることとする。

## 5. ベース・レジストリの指定

各分野において、ベース・レジストリとして適当なデータ項目等を下表のとおり指定する。指定は以下の区分による。

- 区分①：即効性の観点から、早期にベース・レジストリとしての利活用を実現するものとして指定するデータ

## 6. 指定したデータの今後の扱い

ベース・レジストリに指定されたデータについて整備が円滑に進むよう、IT総合戦略室（デジタル庁）において、必要なルールやデータ標準の整備、各種ツールの整備等、各府省に対し必要な支援を行う。指定データを保有する府省は、データ標準への準拠、品質フレームワークによる品質評価、参照ルールの徹底（ワンスオンリー手続でベース・レジストリの情報を参照、誤りは管理者に報告し修正・更新）等のルールを適用する。

### アドレス（町字、所在・地番）等の課題と方針（区分②）

現在行政が保有する様々な土地台帳には共通キーが存在せず、各台帳間の表記揺れ等のため、台帳更新の際に不動産登記簿等からデータを入手しても手作業で再入力するなど膨大な作業時間が発生している。このため、町字、所在・地番、不動産番号をベース・レジストリとして指定し、これらを共通キーとして各台帳の紐付けを可能とする。

- 地番は個人情報に該当する場合があるとされ、少なくとも行政機関間での扱いの整理が課題。
- 町字・所在・地番表記の揺れに対するクレンジングや情報提供のあり方（API・地図データのXML形式提供）も課題。
- 地図データ（不動産登記情報）の約4割は地籍調査等を経ていない古い公図のままで、正確な緯度経度が確定できない任意座標系に基づく。公共座標系（測量法第11条基準）の付与が必要。
- これらを整理し、2025年までに公共座標系の付与された地図データを含む台帳間連携の実現を目指す。

## 7. 指定したデータ以外のデータの今後の扱い

指定を見送ったデータは、各府省の既存データのクレンジング等で品質を確保し、又は既存データをマッシュアップして新たなデータセットとして整備するなど、ベース・レジストリ指定に向け引き続き取り組み、順次指定していく。各府省からベース・レジストリ指定の要望がある場合、上記4の観点に照らし順次指定していく。
