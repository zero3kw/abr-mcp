# abr-spec-build

ABR の公式「データフォーマット（仕様確定版）」xlsx を、abr-mcp が読む項目定義 Markdown
（`specs/20240115_policies_base_registry_format_01.md`）に変換する。**元の xlsx を正**とする。

## 手順

1. openpyxl を入れる（実行時の MCP には不要な、変換専用の依存）:

   ```
   pip install openpyxl
   ```

2. 同梱スクリプトを実行する（公式 URL から xlsx を取得して変換）:

   ```
   python3 .claude/skills/abr-spec-build/build_spec.py
   ```

   - ローカルに xlsx がある場合: `--xlsx <path>`
   - 出力先を変える場合: `-o <out.md>`（既定はリポジトリの `specs/…md`）

3. 生成後、MCP サーバが全データセットをパースできるか確認する
   （`list_datasets` が 13 データセットを返す）。

## 仕様（スクリプトが行う変換）

- 出力対象は xlsx の13データセットシート（`01都道府県`〜`13住居表示-住居位置参照`）。
  `表紙`・`改訂履歴`・`データ項目定義書について` は出力しない。
- 各シートの列1〜8（項目No./項目名/項目名(日本語表記)/データ型/桁数/Not Null/Key/説明）を
  Markdown 表にする。列9以降の「収録例」は出力しない。
- セル内の改行・全角空白は半角空白に均し、`|` はエスケープする。
- 見出しは `# <シート名>(<物理テーブル名>)`。

## 重要: 物理テーブル名は xlsx に無い

xlsx のセルには物理名（`mt_pref`, `mt_town_fullset` 等）が**含まれない**（日本語名のみ）。
そのためスクリプト内の対応表 `IDS`（シート名→物理名）で補っている。**新フォーマットで
シート構成が変わったら `IDS` を更新する**こと。物理名は公式のファイル名／CSVカラム接頭辞に
合わせる（例: 地番は `mt_parcel`）。

## 新フォーマットへの差し替え

ABR が新しいデータフォーマットを公開したら、`build_spec.py` 内の `URL` を新 xlsx の URL に
更新し、必要なら `IDS` を見直して再生成する。出力ファイル名も新しい版に合わせて改名する。
